---
title: Chunk for RAG
description: Split documents into structure-aware chunks sized for your embedding model
---

Add `options.chunking` to a Markdown request to get the document split into chunks that fit your embedding model, each with the headings it sits under and its position in the Markdown. One request replaces a parser, a splitter and a token counter in your pipeline.

```shell
curl http://127.0.0.1:8000/v1/markdown \
  -H 'Authorization: Bearer dev' \
  -F 'metadata={"options": {"chunking": {"maxTokens": 64}}};type=application/json' \
  -F file=@pricing.html
```

## How documents are split

- **Sections first.** A chunk never spans two headings or two slides, so every chunk is about one topic.
- **Tables by rows.** A table larger than the budget splits between rows, and every part repeats the header row, so each chunk stays readable on its own.
- **Code by structure.** Code splits along functions and classes, and every chunk is a complete fenced block with its `language`.
- **Prose by size.** Long sections split into chunks of at most `maxTokens`.

Every chunk reports:

| Field | Use it to |
|---|---|
| `kind` | Treat `text`, `table` and `code` differently, for example a different embedding prompt per kind |
| `headings` | Prefix the chunk with its section path before embedding, or show it as a breadcrumb in results |
| `start`, `end` | Highlight the hit in `result.content`; the span excludes any overlap |
| `tokens` | Check the budget, or sum the cost of an index before you send it |
| `slide` | Link a hit to its slide, for PowerPoint sources |

## Pick the options

| Option | Default | How to choose |
|---|---|---|
| `maxTokens` | `512` | Your embedding model's input limit or your retrieval sweet spot, `64` to `8192` |
| `tokenizer` | `o200k_base` | The tokenizer of your model: `o200k_base` for GPT-4o and later, `cl100k_base` for GPT-4 and `text-embedding-3`, `word` or `character` for other models |
| `overlap` | `0` | Tokens of the next prose chunk appended to each prose chunk, so sentences cut at a boundary appear in both; must be below `maxTokens` |

`"chunking": {}` turns chunking on with every default. When your model has no listed tokenizer, `word` with a `maxTokens` well below its limit is a safe start.

## What to expect

- A heading directly followed by a table becomes its own small text chunk, as `## Response times` above. The table chunk still lists the heading in `headings`, so filter chunks with only a heading line if they add noise to your index.
- Overlap applies to prose only and is taken from the next prose chunk, which may come after a table.
- Content without headings, such as most PDFs, splits by size only and every chunk has empty `headings`.

## Store or download the chunks

With chunking, `output: file` returns the full JSON document, envelope and chunks, as `application/json` instead of the bare Markdown. With a `destination`, the same JSON document is uploaded and the response omits `content` and `chunks`:

```json
{"source": "s3://prod/handbook/sla.html", "destination": "s3://prod/chunks/sla.json", "options": {"chunking": {"maxTokens": 512}}}
```
