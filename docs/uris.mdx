`source` and `destination` are URIs. The scheme decides where Papyrus reads from or writes to.

| URI | Reads | As `source` | As `destination` |
|---|---|---|---|
| `file://<part>` | the multipart part named `<part>` | yes, multipart requests only | no |
| `http://…`, `https://…` | the URL, following redirects | yes | no |
| `<protocol>://<connector>/<path>` | the object `<path>` in a configured connector | yes | yes |

## Uploads

`file://file` is the default `source` of a multipart request and reads the `file` part. Sending `file://` in a JSON request fails with `422 unsupported_uri`, since there is no part to read.

## URLs

Papyrus downloads the URL, follows up to 5 redirects and reports the final URL and HTTP status in `source.fetch`. The server fetch policy applies to every hop:

- URLs that resolve to private or internal addresses fail with `403 source_forbidden`, unless the server sets `http.allow_private`.
- When the server sets `http.allowed_hosts`, any other host fails with `403 source_forbidden`.
- A `404` or `410` from the remote server fails with `404 source_not_found`; any other error status with `502 source_fetch_failed`.

`source.name` is the file name the server sends in `Content-Disposition`, else the last segment of the URL path, or `source` when the path is empty. When the name has no extension, one is added from the `Content-Type`, as for `https://axelered.com`.

## Share links

A public share link opens a viewer page, not the file. Papyrus recognizes these links, downloads the file they share and names the provider in `source.fetch.link`:

| Provider | `link` | Links | Downloads |
|---|---|---|---|
| Google Drive | `google-drive` | `drive.google.com/file/d/…`, `drive.google.com/open?id=…` | the uploaded file as is |
| Google Docs, Sheets, Slides | `google-docs` | `docs.google.com/document/d/…`, `/spreadsheets/d/…`, `/presentation/d/…` | an export to `docx`, `xlsx` or `pptx` |
| Dropbox | `dropbox` | `www.dropbox.com/s/…`, `www.dropbox.com/scl/fi/…` | the file |
| OneDrive, SharePoint | `onedrive` | `1drv.ms/…`, `onedrive.live.com/…`, `<tenant>.sharepoint.com/:w:/…` | the file |
| GitHub | `github` | `github.com/<owner>/<repo>/blob/<ref>/<path>` | the raw file |

- The link must be shared with anyone who has it. A private link returns a sign-in page, which fails with `403 source_forbidden` instead of being processed as a web page.
- Short links that redirect to a share link, such as `bit.ly`, work too: the link is recognized on the hop that reaches it.
- Folder links fail with `422 unsupported_uri`.
- A Google export URL you send yourself, such as `…/export?format=pdf`, is kept as is.
- `/v1/screenshot` opens every URL as a web page, share links included.
- Operators can turn this off with `http.shared_links`.

## Storage connectors

A connector is a named storage location in the server configuration, such as an S3 bucket. With a connector named `prod` using the `s3` protocol, `s3://prod/reports/q3.pdf` is the object `reports/q3.pdf` in it:

```shell
curl http://127.0.0.1:8000/v1/markdown \
  -H 'Authorization: Bearer dev' \
  -H 'Content-Type: application/json' \
  -d '{"source": "s3://prod/reports/q3.pdf", "destination": "s3://prod/markdown/q3.md"}'
```

- The connector name comes from the configuration, not from your bucket name. An unknown name fails with `422 unknown_connector`, and a protocol other than the connector's with `422 unsupported_uri`.
- The path is used as is, without percent-decoding, so object keys round-trip exactly.
- A missing object fails with `404 source_not_found`; a failed upload with `502 destination_failed`.
- The connector and protocol of a destination are checked before processing starts.

Operators add connectors in [configuration](./configuration).
